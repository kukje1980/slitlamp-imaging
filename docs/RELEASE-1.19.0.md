# SlitLamp v1.19.0

극한 상황 테스트(동시 저장 · 디스크 가득 참 · 카메라 끊김 · 강제 종료 등)로 찾은 **영상 유실 · 환자 혼동 위험을 고치고**,
**동영상 화질을 일반 / 고화질 중에서 고를 수 있게** 했으며, 설정 창에 **컴퓨터 사양(최소 · 권장) 안내**를 넣었습니다.
저장소가 `kukje1980/slitlamp-imaging` 으로 옮겨진 뒤 첫 정식 배포판입니다 (v1.18.5 이후 main 에 들어온 변경을 모두 포함).

## 영상 유실 · 환자 혼동 위험 수정 (#45)
- **같은 순간 저장 시 덮어쓰기**: 같은 밀리초에 찍힌 사진, 폴더 이름이 같아지는 두 환자(예: 차트번호 `A/1` 과 `A:1`), 여러 스레드의
  동시 저장이 같은 파일 이름을 골라 서로 덮어썼습니다 → 이미 있는 파일은 절대 덮어쓰지 않고 `_2`, `_3` … 를 붙입니다 (내보내기 사본도 같음).
- **녹화 중 환자 전환**: 녹화를 계속해 새 환자의 눈이 앞 환자 영상에 저장됐습니다 → 환자를 바꾸면 녹화를 끝내 시작한 환자에게 저장합니다.
- **동영상 손상**: 녹화 길이를 벽시계로 재서 시계가 바뀌면 ±1시간으로 기록되던 것, 인코더가 늦을 때 아직 쓰는 중인 파일을 지우거나
  내보내기로 복사하던 것(Explorer 판 포함), 4K 녹화 대기 메모리가 3GB 까지 쌓이던 것(→ 약 800MB 제한)을 고쳤습니다.
- **저장 실패**: 아주 긴 / 한글 차트번호(이름 한 칸 255바이트 초과), CON · NUL 같은 장치 이름, 끝의 점, 잘못된 폴더 규칙, 메모장으로 고친
  설정 파일(BOM) 때문에 저장이 전부 실패하거나 저장 폴더가 기본값으로 바뀌던 문제.
- **웹**: 앞뒤 공백만 다른 차트번호가 다른 환자로 등록되던 것, 검색의 `%` `_` 가 와일드카드로 동작하던 것, 영상 삭제가 미디어 폴더 밖
  파일을 지울 수 있던 것, 카메라가 끊겨도 '녹화 중' 으로 보이던 것, 녹화 · 저장 중 새로고침 때 영상이 조용히 사라지던 것.
- 테스트: 데스크탑 `tests/test_extreme.py` 91개 · 웹 `web/tests/test_extreme.py` 73개 · 실제 브라우저 시험 `web/tests/e2e_extreme.js` 14개 시나리오.

## 동영상 화질 일반 / 고화질 (#45)
설정 → 카메라 · 저장 → **동영상 화질**. 기본은 **일반**입니다.
- 앱(H.264): 일반 CRF 23 · 고화질 CRF 18(원본과 눈으로 구분이 어려운 수준, 파일 약 2배). 두 모드 모두 실시간(30fps)이 되도록
  해상도에 맞는 압축 속도를 씁니다 (1080p veryfast · 4K ultrafast). 예전 설정(medium · CRF 10)은 4코어 PC 에서 1080p 6fps · 4K 2fps 라
  녹화가 끊기고 정지 후 마무리에 10초 넘게 걸렸습니다 — 그래서 **기본 녹화 화질이 예전보다 낮아집니다** (필요하면 고화질을 고르세요).
- 웹(브라우저 녹화): 비트레이트를 해상도에 맞춰 고정 (일반 1080p 5Mbps · 4K 20Mbps, 고화질 2.5배). 지정하지 않으면 브라우저 기본값(낮음)으로 녹화됐습니다.

## 설정 → 컴퓨터 사양 (#1)
- 앱: 설정 창 '컴퓨터 사양' 탭 — 최소 · 권장 사양 표, 동영상 화질 모드 설명, 그리고 **이 PC 의 운영체제 · 코어 수 · 메모리 · 저장 폴더 여유
  공간을 읽어 권장 충족 / 최소 충족 / 미달을 판정**합니다 (4코어 · 8GB = 최소, 6코어 · 16GB = 권장, 여유 50GB 미만 경고).
- 웹: 설정 → 컴퓨터 사양 → 설명 창. README 에도 같은 표가 있습니다.
- **최소**(1080p 촬영 · 녹화가 끊기지 않는 선): Windows 10 64비트(22H2) / 11 · macOS 14 이상, 4코어 CPU, 8GB, 내장 그래픽, SSD 256GB(여유 50GB).
  **권장**(4K · 고화질까지 여유 있게): 6코어 이상, 16GB, NVMe SSD 1TB + 백업, USB 3.0 직결. 그래픽카드는 둘 다 필요 없습니다 (압축은 CPU).
