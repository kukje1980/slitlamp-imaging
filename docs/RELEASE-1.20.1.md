# SlitLamp v1.20.1

v1.20.0 에 새로 들어온 **외장 하드 백업 · 사진 삭제** 기능을 극한 상황(설정 파일 손수정 · 복사 중 하드 빠짐 · NAS 끊김 ·
같은 파일을 가리키는 두 기록 · 녹화 중 삭제 · 환자 전환 뒤 Pro 삭제 · 보기 창 Delete 키 · 2,400장 환자 · 업로드 · 삭제 동시 폭주)으로
시험해 찾은 **환자 영상을 잃을 수 있는 결함 5개를 고친 안전 수정판**입니다. 기능 변화는 없습니다.

## 백업 안전 수정
- **백업 위치가 사진 폴더(또는 참조 영상 폴더) 안이면 실행할 때도 거부합니다.** 설정 창만 막혀 있어, 설정 파일을 메모장으로 고쳤거나
  사진 저장 폴더를 나중에 백업 위치의 위 폴더로 바꾸면 그대로 돌아 **백업이 자기 자신을 다시 복사해 돌 때마다 두 배**로 커지면서도
  '백업 ✓' 로 보였습니다 → '백업 실패' 로 알리고 복사하지 않습니다. 사진 폴더 안에 백업 폴더(backup_info.json 이 있는 폴더)가 있어도 그 안은 건너뜁니다.
- **복사 도중 외장 하드가 빠지면** 폴더 만들기가 **내장 디스크에 같은 이름의 폴더를 다시 만들어 그쪽으로 백업**했습니다
  (맥은 `/Volumes/이름` 폴더가 남으면 다음에 하드를 꽂아도 '이름 1' 로 붙어 백업이 영영 내장 디스크로 갑니다) → 파일마다 복사 직전과
  바꿔 넣기 직전에 백업 폴더의 표지 파일(backup_info.json)을 확인하고, 없으면 방금 만든 빈 폴더를 되돌리고 '백업 드라이브 없음' 으로
  멈춥니다. 다시 꽂으면 빠져 있던 동안의 사진부터 이어서 백업합니다 (반쯤 복사된 파일은 남지 않음).
- **사진 저장 폴더(NAS 등)가 끊겨 있으면 '백업 ✓'** 로 보였습니다 — 사진을 하나도 못 봤는데 끝난 것처럼 → 환자 기록 DB 는 백업하되
  '사진 저장 폴더를 찾을 수 없어 사진 · 동영상은 백업하지 못했습니다' 경고(⚠)로 남기고, 다음 확인 때 다시 봅니다.

## 삭제 안전 수정
- **같은 파일을 가리키는 두 기록 중 하나를 지우면 파일까지 지워져 다른 기록의 영상이 사라졌습니다.** (DB 복원 · 샘플 가져오기 · 날짜 수정으로
  생길 수 있음 — 영상 삭제 · 그날 삭제 · Explorer 판의 영상 · 검사 삭제 모두) → 다른 기록이 아직 쓰는 파일은 남기고, 마지막 기록을 지울 때만
  파일을 지웁니다.
- 웹: 촬영일 삭제 확인 창에 **누구의 영상인지(환자 이름)** 를 표시합니다 (앱과 같게).

## 시작 안전 수정
- **처음 실행 때 샘플 사진 등록이 DB 잠김 · 메모리 부족 등 파일 오류가 아닌 이유로 실패하면 프로그램이 켜지지 않았습니다**
  (파일 오류만 잡았음) → 어떤 오류든 기록만 남기고 켜져 촬영할 수 있습니다. 샘플 등록은 다음 실행 때 다시 시도합니다.

## 확인한 것 (문제 없음)
녹화 중 사진 · 그날 삭제가 녹화 파일을 건드리지 않음 · 환자 전환 뒤 Pro 삭제 대상이 남지 않음 · 보기 창 Delete 키는 확인 창을 거치고
Enter 는 닫기 · 연속 촬영으로 보기 창이 닫혀도 삭제되지 않음 · 2,400장 환자 선택과 그날 삭제 · DB 를 쓰는 중에 만든 백업 사본의 무결성 ·
백업 중 계속 촬영해도 모두 백업 · 백업 폴더를 지워도 원본 무사 · 복사 못 한 파일 하나가 나머지를 막지 않음 · 웹 삭제가 미디어 폴더 밖
링크를 따라가지 않음 · 폴더 이름이 같아지는 두 환자 중 하나를 지워도 다른 환자 파일 유지 · 지운 영상 번호 재사용 없음 ·
업로드 · 삭제 동시 폭주 뒤 DB 와 디스크 일치.
