# 다음 배포에 들어갈 변경 (아직 배포 안 함)

변경은 이 브랜치에만 모아 두고, **최종 배포 때** 버전 번호를 정해(앱 · 설치파일 · 웹 버전 파일, docs/RELEASE-x.y.z.md,
VERSIONS.md, README) main 에 합쳐 한 번에 배포한다. 배포하면 이 목록은 그 버전의 릴리스 노트로 옮기고 비운다.

마지막 배포판: v1.20.0 (2026-10-30) — [docs/RELEASE-1.20.0.md](RELEASE-1.20.0.md)

- **외장 하드 · 다른 드라이브로 백업 (실시간 · 자동 · 수동)** — 설정 → '백업' 탭, 상태줄 오른쪽 '백업 ✓ 14:32' 버튼
  (Explorer 판은 파일 메뉴 '외장 하드로 지금 백업' 도). **실제 외장 하드 · Windows 장비에서는 아직 확인하지 못했습니다** (임시 폴더로 시험).
  - 백업 폴더 이름 = 백업을 시작한 날짜 + 마지막으로 백업한 날짜 (YYMMDDYYMMDD). 2021-09-08 에 시작해 2026-10-28 까지 백업했으면
    `210908261028`. 날짜가 바뀐 뒤 처음 백업할 때 뒤의 날짜가 오늘로 바뀝니다 (폴더 이름 바꾸기 — 그 폴더의 파일을 다른 프로그램이
    열어 두어 못 바꾸면 알리고 그 폴더에 계속, 다음 백업 때 다시). '새 백업 폴더 시작' 은 지금 폴더를 그대로 두고 오늘 날짜로 새로.
    같은 이름이 있으면(다른 PC 가 같은 날 시작) 뒤에 -2 · -3. 외장 하드를 여러 개 번갈아 써도 하드마다 자기 폴더가 이어집니다.
  - 백업하는 것: 사진 · 동영상 · 썸네일(media), 참조 영상 라이브러리, 환자 · 검사 · 영상 기록 DB(쓰는 중에도 일관된 사본 +
    날짜별 사본 `db/history/slitlamp-YYYYMMDD.db` 60일), 설정(config.json), '복원 방법.txt'. 원본은 읽기만 하고 바꾸지 않습니다.
  - 자동(기본): 사진 · 동영상을 저장하는 즉시 복사(실시간), 켤 때(20초 뒤) · 30분 / 1시간 / 4시간 / 하루마다 빠진 파일 확인,
    DB 가 바뀌면 30초 안에 DB 다시 백업. 수동: '지금 백업' 을 누를 때만. 닫을 때 남은 것(DB · 못 한 파일, 수동이면 전체)을 마무리
    (끌 수 있음, '건너뛰기' 가능).
  - 두 번째부터는 새 파일 · 바뀐 파일만 복사 (같은 크기 · 수정 시각 ±2초). 녹화 중인 동영상은 끝난 뒤에. 임시 이름에 다 쓰고
    디스크에 내린 뒤 바꿔 넣어, 하드를 뽑거나 꺼져도 반쯤 복사된 파일이 진짜처럼 남지 않습니다. 프로그램에서 지운 사진도 백업에는 남깁니다.
  - 외장 하드가 빠지면 '백업 드라이브 없음', 다시 꽂으면 빠져 있던 동안 저장한 사진부터 이어서. 여유 200 MB 아래면 멈추고
    '백업 드라이브 가득 참'. 사진 폴더 안 · 백업 폴더 자체는 고를 수 없고, 사진과 같은 드라이브면 경고(하드 고장 대비가 안 됨).
  - 복원 화면은 없습니다 — 각 백업 폴더의 '복원 방법.txt' 대로 파일을 원래 위치에 복사합니다. 웹 버전은 해당 없음.
- **극한 상황 테스트 2 (백업 · 삭제) 로 찾은 안전 수정** — `tests/test_extreme_v120.py` 25개 · `web/tests/test_extreme_v120.py` 7개 ·
  브라우저 시험 `web/tests/e2e_extreme.js` 에 삭제 시나리오 추가.
  - **백업 위치가 사진 폴더 안이면 실행할 때도 거부**: 설정 창은 막았지만 설정 파일을 손으로 고쳤거나 사진 폴더를 나중에 백업 위치의
    위로 바꾸면 그대로 돌아 **자기 자신을 복사해 돌 때마다 두 배**로 커졌습니다 → '백업 실패' 로 알리고 복사하지 않습니다.
    사진 폴더 안에 백업 폴더(backup_info.json 이 있는 폴더)가 있어도 그 안은 건너뜁니다.
  - **복사 도중 외장 하드가 빠지면** 폴더 만들기(mkdir)가 **내장 디스크에 같은 이름의 폴더를 다시 만들어 그쪽으로 백업**했습니다
    (맥은 /Volumes/이름 폴더가 남으면 다음에 하드를 꽂아도 '이름 1' 로 붙어 백업이 영영 내장 디스크로 감) → 파일마다 복사 직전 · 바꿔 넣기
    직전에 백업 폴더의 표지 파일을 확인하고, 없으면 방금 만든 빈 폴더를 되돌리고 '백업 드라이브 없음' 으로 멈춥니다. 다시 꽂으면 이어서.
  - **사진 폴더(NAS 등)가 끊겨 있으면 '백업 ✓'** 로 보였습니다 (사진을 하나도 못 봤는데) → 환자 기록 DB 는 백업하되 '사진 저장 폴더를
    찾을 수 없어 사진 · 동영상은 백업하지 못했습니다' 경고(⚠)로 남깁니다.
  - **같은 파일을 가리키는 두 기록 중 하나를 지우면 파일까지 지워져** 다른 기록의 영상이 사라졌습니다 (DB 복원 · 가져오기 · 날짜 수정으로
    생길 수 있음, 앱의 영상 삭제 · 그날 삭제 · Explorer 의 영상 · 검사 삭제 모두) → 다른 기록이 아직 쓰는 파일은 남기고 마지막 기록을
    지울 때만 파일을 지웁니다.
  - **시작 때 샘플 사진 등록이 DB 잠김 등으로 실패하면 프로그램이 켜지지 않았습니다** (파일 오류만 잡았음) → 어떤 오류든 기록만 남기고 켜집니다.
  - 웹: 촬영일 삭제 확인 창에 누구의 영상인지(환자 이름) 표시 (앱과 같게).
  - 확인한 것(문제 없음): 녹화 중 사진 · 그날 삭제가 녹화 파일을 건드리지 않음, 환자 전환 뒤 Pro 삭제 대상이 남지 않음, 보기 창 Delete 키는
    확인 창을 거치고 Enter 는 닫기, 연속 촬영으로 보기 창이 닫혀도 삭제되지 않음, 2,400장 환자 선택 · 그날 삭제, DB 쓰는 중 백업 사본의
    무결성, 백업 중 계속 촬영, 백업 폴더를 지워도 원본 무사, 웹 삭제가 미디어 폴더 밖 링크를 따라가지 않음, 폴더가 같아지는 두 환자 중
    하나를 지워도 다른 환자 파일 유지, 지운 영상 번호 재사용 없음, 업로드 · 삭제 동시 폭주 뒤 DB 와 디스크 일치.
